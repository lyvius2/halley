# 한도가 끝나도 서비스는 이어진다 — 경로 산출 사다리

> **상태: 계획 (미구현).** 설계 [I273] 의 본문입니다.
> 착수할 때 이 문서를 먼저 읽고, 결정이 바뀌면 여기를 고친 뒤 코드를 고치십시오.

---

## 무슨 일이 있었나

2026-09-03, 카카오 길찾기와 ODsay 의 **하루 한도가 같은 날 함께 끝났습니다.**

```
04:46  {"code":-10,"msg":"API limit has been exceeded."}   ← 카카오 길찾기
       → CircuitBreaker 'kakao-directions' is OPEN
04:51  code=429, msg=Too Many Requests                      ← ODsay
       → LLM 대체 → Claude read timeout(60초) ×2 → 0 of 9
04:54  CircuitBreaker 'claude-llm' is OPEN
       → "LLM is busy - waiting 2000ms" → 실패 → 반복 … 몇 분
```

임장 플래너가 통째로 멈췄습니다. 화면에는 구간마다 `999분`, 합계 `3996분` 이
찍혔고 지도에는 직선만 그려졌습니다.

### 이미 고친 것

| | 무엇을 | 어디에 |
|---|---|---|
| [I270] | 모르는 것을 **999분이라 부르지 않는다**. 한도를 하루 기억한다 | 구현됨 |
| [I271] | 열린 차단기에 다시 안 던진다. 못 받은 것도 기억한다. 행렬이 기억을 본다 | 구현됨 |
| [I272] | 한 번 받은 길은 **다시 안 받는다** (좌표+출발시각, TTL 24h) | 구현됨 |

**이 셋은 "잘 죽는 법"입니다.** 이 문서는 **"안 죽는 법"** 입니다.

## 사다리

```
① 한도를 미리 안다        ← 부르기 전에 안다. 헛걸음을 안 한다
      ↓ 카카오가 잠겼다
② TMAP 으로 넘어간다      ← 한도가 둘로 갈린다
      ↓ 둘 다 잠겼다
③ LLM 에게 동선을 묻는다   ← 지도는 직선, 안내는 LLM 의 말
      ↓ LLM 도 안 된다
④ 내일 다시 오시라고 말한다
```

**각 칸이 실패해도 다음 칸이 받습니다.** 지금은 ①이 없어서 ②·③이 있어도
헛걸음을 계속합니다 — 그래서 ①이 먼저입니다.

## ① 한도를 미리 안다 — Redis 잠금

### 왜 Redis 인가

지금은 `DirectionsQuota`·`TransitWithLlmFallback.exhaustedOn` 이 **인스턴스
메모리**에 있습니다. 두 가지가 문제입니다.

- **다시 띄우면 잊습니다.** 배포 한 번에 하루치를 또 태웁니다
- **자정 처리를 손으로 합니다.** `LocalDate.now().equals(exhaustedOn)` 은 날짜
  비교라 되긴 하지만, 여러 곳에 흩어집니다

Redis 는 **TTL 하나로 둘 다 해결합니다.** 다음 자정까지 남은 초를 TTL 로 주면
**자정에 저절로 풀립니다.**

### 모양

```
키    quota:{api}:{yyyy-MM-dd}        예) quota:kakao-directions:2026-09-03
값    "1"
TTL   다음 자정(KST)까지 남은 초
```

```java
public interface QuotaGate {

    /** 부르기 <b>전에</b> 본다. 잠겼으면 아예 안 부른다 */
    boolean exhausted(ExternalApi api);

    /** 한도를 봤다. 오늘은 끝이다 */
    void markExhausted(ExternalApi api);

    /** 오늘 몇 번 불렀나 — 관리자 화면이 본다 (선택) */
    long callsToday(ExternalApi api);
}
```

`ExternalApi` 는 열거형입니다 — `KAKAO_DIRECTIONS` · `ODSAY_TRANSIT` ·
`MINISTRY_TRADE` · `CLAUDE_LLM` … 이름을 문자열로 흩뿌리면 오타 하나가 조용히
다른 잠금을 만듭니다.

### 자정까지 남은 초

```java
private static Duration untilMidnight() {
    final ZonedDateTime now = ZonedDateTime.now(KST);
    return Duration.between(now, now.toLocalDate().plusDays(1).atStartOfDay(KST));
}
```

**KST 로 고정합니다.** 서버가 UTC 로 돌면 한국 자정이 아니라 오전 9시에 풀립니다 —
공공 API 의 하루는 한국 시각 기준입니다.

### 카운터는 선택

`INCR quota:count:{api}:{date}` + 같은 TTL 로 **오늘 몇 번 불렀는지**를 셀 수
있습니다. 한도를 미리 알 수 있는 API 는 **닿기 전에** 잠글 수 있습니다.

> 다만 **한도 값을 우리가 모르는 API 가 많습니다.** 세는 것은 관리자 화면에
> 보여 주는 값으로 두고, 잠금은 **실제 한도 응답을 본 순간**에 거는 것이 안전합니다.
> 추측한 한도로 먼저 잠그면 **쓸 수 있는데 안 쓰게** 됩니다.

### 무엇을 옮기나

| 지금 | 뒤에 |
|---|---|
| `DirectionsQuota` (인스턴스 메모리) | `QuotaGate` (Redis) |
| `TransitWithLlmFallback.exhaustedOn` | 〃 |
| `LlmAvailability` ([I271]) | **그대로 둡니다** — 차단기는 하루가 아니라 <b>60초</b>짜리이고 성격이 다릅니다 |

### 관리자 화면

설정 화면에 **오늘의 한도 상태**를 보여 줍니다. 지금은 로그를 봐야만 압니다.

```
카카오 길찾기   🔒 오늘 한도 소진 (자정에 풀림)   호출 1,043회
ODsay          🔒 오늘 한도 소진               호출 302회
국토부 실거래    ✅ 정상                        호출 88회
```

## ② TMAP 으로 넘어간다

### 카카오맵에 그릴 수 있는가 — **그렇습니다**

TMAP 경로 API 는 **WGS84 좌표**를 돌려줄 수 있고, 카카오맵 JS SDK 의
`Polyline` 은 좌표 목록만 있으면 그립니다. **좌표계가 맞으면 어느 쪽이 만든
선이든 그립니다.**

```
TMAP  POST /tmap/routes?version=1
      reqCoordType=WGS84GEO   ← 보낼 때
      resCoordType=WGS84GEO   ← 받을 때  ★ 이걸 안 주면 다른 좌표계로 온다
      → GeoJSON features[].geometry.coordinates  [lng, lat]
```

**착수할 때 반드시 실물로 확인하십시오.** 이 프로젝트가 [I268]에서 배운 것입니다 —
"안 될 것이다"도 "될 것이다"도 **재 보기 전에는 추측**입니다. 호출 한 번이면 압니다.

```bash
curl -X POST 'https://apis.openapi.sk.com/tmap/routes?version=1' \
  -H 'appKey: <KEY>' -H 'Content-Type: application/json' \
  -d '{"startX":"127.0","startY":"37.5","endX":"127.1","endY":"37.6",
       "reqCoordType":"WGS84GEO","resCoordType":"WGS84GEO"}'
```

확인할 것 셋:
1. `resCoordType=WGS84GEO` 로 받은 좌표가 **카카오맵 위에 제자리에 얹히는가**
2. **출발 시각 지정**이 되는가 — [I196]이 요구합니다. 안 되면 "지금 기준"임을
   화면이 말해야 합니다
3. **약관.** 한 공급자의 경로 데이터를 다른 공급자의 지도에 얹는 것이 양쪽
   약관에 걸리지 않는지 — **이건 코드로 확인할 수 없습니다.** 사람이 읽어야 합니다

> 3번이 걸리면 ②를 건너뛰고 ①→③ 으로 갑니다. 사다리는 그래도 섭니다.

### 붙이는 자리

[I272]에서 이미 자리를 만들어 두었습니다.

```
ItineraryService → KakaoDirectionsPort
                       ↑
                  CachingDirections   ← 담아 두기 (공급자 무관)
                       ↑
                  DirectionsChain     ← ★ 새로 넣을 자리
                     ↙        ↘
        KakaoDirectionsAdapter   TmapDirectionsAdapter
```

`DirectionsChain` 이 하는 일은 하나입니다 — **잠기지 않은 공급자를 고른다.**

```java
for (final Directions provider : providers) {          // 카카오 → TMAP 순
    if (quotaGate.exhausted(provider.api())) continue;
    final DriveRoute route = provider.findRoute(...);
    if (route.isComputed()) return route;
}
return DriveRoute.missing();                            // ③ 으로 넘어간다
```

**포트 이름을 바꿔야 합니다.** `KakaoDirectionsPort` 는 이제 카카오만의 것이
아닙니다 — `DirectionsPort` 로 고칩니다. 이름이 거짓말을 하면 다음 사람이
카카오 전용인 줄 압니다.

### 캐시는 그대로

같은 좌표·같은 시각이면 **어느 쪽이 답했든 같은 답**입니다. [I272]의 캐시는
공급자를 안 봅니다. 다만 담을 때 **누가 답했는지**는 남깁니다 — 값이 이상할 때
어느 공급자 탓인지 알아야 합니다.

## ③ LLM 에게 동선을 묻는다

**대원칙입니다.** 자가용이든 대중교통이든 API 가 다 잠기면, **좌표가 아니라
이름과 주소로** 묻습니다.

### 왜 이게 되는가

LLM 은 **서울 지리를 압니다.** 좌표 쌍마다 몇 분인지는 못 맞히지만,
"미사는 하남이라 뚝 떨어져 있으니 아침에 먼저" 같은 **동선의 뼈대**는 냅니다.
사람이 손으로 짜던 것과 같은 종류의 판단입니다.

### 프롬프트

지금 있는 `LlmTransitEstimator` 와 **다릅니다.** 그건 구간마다 분을 묻고,
이건 **순서를 묻습니다.**

```
주말에 임장을 가려고 합니다. 아래가 후보입니다.
하루에 다닐 수 있는 최적의 루트를 짜 주십시오.

- 상계주공7단지 (서울 노원구 상계동 692)
- 화랑대역 태강아파트 (서울 노원구 공릉동 81)
- 석관래미안 (서울 성북구 석관동 407)
- 정릉 한화포레나1단지 (서울 성북구 정릉동 1037)
- 미사강변트래지안아파트 (경기 하남시 망월동 938)

출발지: 경기 고양시 덕양구 화중로 219
출발 시각: 2026-09-05(토) 09:00
매물당 체류: 25분

아래 JSON 만 출력하십시오.
{"order":[{"name":"...","arriveAt":"HH:mm","fromPreviousMinutes":40,
           "note":"미사에서 약 40분. 언덕 위치라 주차 동만 미리 물어보세요"}],
 "reason":"이 순서로 짠 이유 두세 문장"}
```

**주소를 함께 줍니다.** 이름만으로는 같은 이름의 다른 단지를 집습니다 —
[I268]에서 `석관래미안 101동` 이 680m 떨어진 남의 단지를 물어 온 것과 같은 위험입니다.

### 화면이 무엇을 보여 주나

| | 무엇 |
|---|---|
| 지도 | **직선**으로 잇습니다. 있지도 않은 길을 그리지 않습니다 ([I177]·[I210]과 같은 원칙) |
| 안내 레이어 | LLM 이 준 순서·시각·메모를 그대로 |
| 표시 | **「AI 추정 동선」** 이라고 분명히. 실제 길찾기가 아니라는 것을 숨기지 않습니다 |

> **좌표를 지어내게 하면 안 됩니다.** [I210]이 정한 것입니다 —
> "있지도 않은 길이 지도에 그려지는 것은 없는 것보다 나쁩니다."
> LLM 에게는 **순서와 대략의 시간**만 묻고, 선은 직선입니다.

### 이 답은 담아 둡니다

같은 매물 묶음·같은 날짜면 **같은 답**입니다. 캐시 열쇠는
`정렬한 매물 id 목록 + 출발지 + 날짜/시각` 입니다. LLM 은 비싸고 느립니다.

## ④ 내일 다시 오시라고 말한다

LLM 마저 안 되면 **모달로 분명히 말합니다.**

```
현재 서비스 부하로 최적 경로 산출이 어렵습니다.
내일 다시 시도해주세요.
```

**빈 화면이나 999분보다 낫습니다.** 사람이 무엇을 해야 할지 아는 것이
이 문구의 값입니다.

응답에 실을 것:

```json
{"status":"UNAVAILABLE",
 "message":"현재 서비스 부하로 최적 경로 산출이 어렵습니다. 내일 다시 시도해주세요.",
 "retryAfter":"2026-09-04T00:00:00+09:00"}
```

`retryAfter` 는 ①의 TTL 에서 그대로 나옵니다 — **언제 풀리는지 우리가 압니다.**

## 어디부터 하나

| | 무엇 | 왜 이 순서인가 |
|---|---|---|
| **1** | ① Redis 한도 잠금 + 관리자 화면 | 이것이 없으면 ②·③ 이 있어도 **헛걸음을 계속**합니다. 그리고 지금 인스턴스 메모리에 있는 것들이 **배포 한 번에 잊힙니다** |
| **2** | ④ 모달 + `UNAVAILABLE` 응답 | 가장 작고, **오늘의 증상을 바로 없앱니다** |
| **3** | ③ LLM 동선 | ②가 약관에 걸릴 수 있으니 **먼저 세워 둡니다.** ②가 없어도 사다리가 섭니다 |
| **4** | ② TMAP | 약관 확인이 먼저입니다. 확인 뒤에 붙입니다 |

**2번을 3번보다 앞에 두는 이유**는, ③이 실패할 때 갈 곳이 ④이기 때문입니다.
받을 곳을 먼저 만들어 둡니다.

## 열어 둔 것

- **약관.** TMAP 경로를 카카오맵에 그리는 것이 양쪽 약관에 걸리는가 — 사람이 읽어야 합니다
- **TMAP 출발 시각.** 지정이 되는지, 안 되면 [I196]을 이 경로에서 어떻게 다룰지
- **한도 값.** 카카오·ODsay 의 하루 한도가 실제로 얼마인지 — 알면 **닿기 전에** 잠글 수 있습니다
- **대중교통 캐시.** [I272]는 자가용만 담습니다. 대중교통은 `travelTimeCache` 가
  **분만** 담고 구간 상세·경로선은 안 담아, 구간 안내가 다시 부릅니다
